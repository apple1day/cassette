# 2026-09-05

## 歌词链路重构（Cassette / Navidrome）

用户反馈：Navidrome 服务器里已有歌词（.lrc 文件 / 内嵌标签），app 显示 "Lyrics not supported"。

### 根因
1. **能力门禁一票否决**（主因）。`LyricsService` 用 `capabilities.supports(.songLyrics)` 卡住请求，
   而 SwiftSonic 的 `fetchCapabilities()` 在 `getOpenSubsonicExtensions` 失败时**静默 catch**，
   扩展表变空字典并被 `loadCapabilities()` 永久缓存 → 一次网络抖动/反代拦截就永久禁用歌词。
   且 `supports` 实现是 `versions.contains(1)`，服务器只声明 v2 也会误判。
2. 只读 `structuredLyrics`，legacy `getLyrics(artist:title:)` 从未调用（SwiftSonic 已实现）。
3. 全项目无 LRC 解析器，纯文本歌词只能整块显示。
4. 语言码严格相等：`zh-CN`/`zho`/`cmn`/`eng` 匹配不上系统 `zh`/`en`。
5. 缓存无 TTL，`fetchedAt` 字段存在但从未用于失效判断。

### 改动
- 新增 `Cassette/Utilities/LyricsParser.swift`（LRC/纯文本 → StructuredLyrics）
- 新增 `Cassette/Utilities/LyricsLanguage.swift`（语言码规范化 + 匹配）
- 重写 `LyricsService`：乐观探测（能力仅作诊断）+ legacy 回退 + 缓存 TTL（synced 7d / unsynced 1d / 负缓存 6h）
  + `invalidate()`；能力表为空且 isOpenSubsonic 时强制 `refreshCapabilities()` 一次
- `LyricsViewModel`：二分查找行定位（遇 nil start 降级线性）、`retry()`、接收 title/artist
- `LyricsView`：三个失败态加 "Try again" 按钮
- 新增 `LyricsParserTests` / `LyricsLanguageTests`，补充 Service 与 ViewModel 测试

### 验证方式（重要，见 MEMORY.md）
xcodebuild 在本环境不可用（SwiftPM 要 spawn 沙盒子进程，被拒）。
改用 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` + `swiftc -typecheck`，
SwiftData 宏用 mock 替身；纯逻辑单独编译成可执行程序跑断言。
二分查找与原线性扫描做了 15 万次随机对比，零差异。

## 第二轮：占位假歌词 + 网易云 JSON 混合格

用户拿网易云下载的真实文件测试（`/Users/even/mine/music/12/`），app 仍显示 "暂无歌词"。

### 根因（新增两类）
6. **下载器占位文件**：网易云下载器在源歌曲没有歌词时写 `[00:00.00]暂无歌词`。
   整库 49 个 lrc 文件里有 14 个是这种假歌词（13%）。app 之前会把它们当合法
   同步歌词渲染，"暂无歌词"四个字直接当成歌词显示。
7. **网易云 yrc 混合格**：真歌词文件前几行是 JSON `{"t":-1000,"c":[{"tx":"作词: "},{"tx":"0"}]}`，
   后面才是标准 LRC。原解析器不认识 JSON，把它们当普通文本渲染成乱码。

### 改动
- `LyricsParser` 新增 `parseNetEaseJSONLine`（处理 `t`/`c`/`tx`，负 `t` 钳为 0）
  + 同时间戳下 LRC 行排在 JSON credits 前面（让标题置首）。
- `LyricsParser.isPlaceholder`（raw 与 structured 两个重载）+ 占位词集合
  （`暂无歌词` / `纯音乐` / `纯音乐，请欣赏` / `此歌曲为没有填词的纯音乐，请欣赏` 等）。
- `LyricsService`：在 `getLyricsBySongId` 之后调 `droppingPlaceholders(list)`，
  在 `legacyFallback` 内部检查 raw 是否占位（占位则 `return nil`）。
- `LyricsParserTests` 增 3 个 suite（NetEaseJSON / Placeholder / 占位结构化条目）。

### 关键经验
- 占位检测**必须**比对整个 line set 而非首行——首行占位但含真歌词要保留。
- JSON 排序的 tie-break 重要：NetEase 用负 `t`（钳 0），标题也是 `[00:00.00]`，
  稳定排序时若不指定 kind rank，"作词: 0" 会跑到标题前面去。
- 同模块编译 SwiftSonic 时 IRGen 会因为 `Codable + same-module retroactive`
  触发 signal 6 崩溃（详见 MEMORY.md）。绕路：先把 SwiftSonic 编译成 dylib
  (`-emit-library`)，再 `-I/-L` 引用。
