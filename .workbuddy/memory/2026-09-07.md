# 2026-09-07

## 调研：Cassette 对接 Jellyfin 后台的可行性

**结论：可行，改造面可控。** 不是「能不能」，而是「在哪一层做适配」。

### 关键事实

1. **协议不通**：本机 `/Users/even/mine/anxiong/jellyList/jellyfin` 是 Jellyfin **12.0.0** master
   （commit 3e7d1158）。全仓库 grep `Subsonic` → **0 命中**，主仓库已无内置 Subsonic API。
   Cassette 只说 Subsonic/OpenSubsonic（SwiftSonic）→ 现状直连不通。
   第三方 Subsonic 插件在 Jellyfin 12 换 EF Core DB 后生态未适配，不建议押注。

2. **改造接缝 = `LibraryServiceProtocol`**（`Cassette/Services/Protocols/`，约 30 个方法）。
   实现一份 `JellyfinLibraryService` 把 REST 响应映射成 SwiftSonic DTO（`Song`/`AlbumID3`/`ArtistID3`），
   UI 层零改动。SwiftSonic DTO 是 public struct + `public let`，可在 Cassette 侧直接构造。

3. **封面层已收口，是好消息**：View 只传 `album.coverArt ?? album.id` 当 id，
   不自己拼 URL；真正拼 URL 的只有 `libraryService.coverArtURL(id:size:)`
   和 `CoverArtView` / `artworkImageCache` 两个统一入口。
   → 只要 Jellyfin 把 `coverArt` 填成 Item Id，`coverArtURL` 里改拼
   `/Items/{id}/Images/Primary` 即可，UI 不用动。

4. **播放链路零改动**：`PlayerService` 已经是
   `audioPlayer.play(url: source.url, headers: source.customHeaders)`，
   AudioStreaming 的 `AudioPlayer.play(url:headers:)` 支持自定义 header
   → Jellyfin 的 `Authorization: MediaBrowser ...Token=...` 塞进 customHeaders 即可。
   Cassette 已有 `Services/Networking/CustomHeadersTransport.swift`（含 Authorization 冲突检测）。

5. **必须收口的 3 处直连 SwiftSonic client**（绕过了 protocol，换后端会失效）：
   - `PlayerService.swift` — `client.streamURL(...)`（371/381/1664 行）+ `client.coverArtURL(id:size:600)`
   - `DownloadService.swift` — `client.coverArtURL(id:size:600)`
   - `ServerService.makeSwiftSonicClient()` — 鉴权工厂绑定 Subsonic token/salt

6. **Jellyfin 侧端点清单**（已在源码确认存在）：
   - 鉴权 `POST /Users/AuthenticateByName` → AccessToken
   - 列表 `GET /Items?IncludeItemTypes=Audio&Recursive=true&ParentId=<albumId>&Fields=...&SortBy=...`
     （`Jellyfin.Api/Controllers/ItemsController.cs`）
   - 音频 `GET /Audio/{itemId}/universal`（转码）/ `stream`（直连 `Static=true`）
   - 歌词 `GET /Audio/{itemId}/Lyrics` → `LyricDto`（**结构化带 Start ticks，比 Navidrome 的 .lrc 更好接**）
   - 封面 `GET /Items/{itemId}/Images/Primary`
   - 收藏 `POST|DELETE /Users/{userId}/FavoriteItems/{itemId}`
   - 相似 `GET /Items/{id}/InstantMix`（对应 smartShuffle / endlessExtension）
   - 上报 `/PlayStart` `/PlaybackStopped` `POST /Playing/{itemId}/Progress`

7. **映射的坑**：
   - `AlbumID3.songCount` / `duration` 是**非可选 Int**，Jellyfin 侧 `ChildCount` /
     `CumulativeRunTimeTicks` 可空且需 `Fields` 显式指定 → 映射时兜底 0。
   - Subsonic 的 `ArtistIndex`（A-Z 字母索引）Jellyfin 没有，要自己按 SortName 首字母分组。
   - Jellyfin ID 是 GUID→字符串，与 Subsonic 字符串 id 体系兼容。
   - `UserData.PlayCount` / `IsFavorite` 可映射 Subsonic 的 `playCount` / `starred`。

8. **注意**：Jellyfin 12 起「API 默认不再允许废弃的鉴权机制」（官方 2026-05 公告），
   → **不要依赖 `api_key` query 参数**，统一走 `Authorization` header。

### 工具坑（重复出现）
本项目环境下 **Bash 里的 `grep` 命令会静默返回空**（沙箱限制），
必须改用 **Grep 工具**；`ls`/`wc`/`sed` 正常。
