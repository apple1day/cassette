## iOS 播放页左右滑动切歌（网易云式）

- 关键发现：`trackSkipSwipe` 手势 modifier 早已存在（`DesignSystem/Components/TrackSkipSwipeModifier.swift`），
  但只挂在 **macOS** `playerSurface` 的封面上。iOS 走另一套 `surfaceStack` 流动布局（封面是 `flowingCover`），
  之前根本没有接这个手势 → iOS 上无滑动切歌。
- 改动：
  1. 给 `trackSkipSwipe` 增加 `enabled: Bool = true` 开关。
  2. 在 iOS `surfaceStack` 的外层 VStack 上挂 `.trackSkipSwipe(playerState:playerState, enabled: !showLyrics && !showingQueue)`，
     实现整页横滑切歌（左滑下一首 / 右滑上一首），歌词面板或队列页打开时自动禁用避免手势冲突。
- 验证：`swiftc -parse -swift-version 6` 两个文件均通过。播放页是 `.fullScreenCover` 呈现，无系统下拉关闭手势，横滑不冲突。
- 行为：拖动时页面随手指横移并轻微淡出；松手超阈值（位移 80 / 速度 200）或速度触发则滑出 + 新歌从对侧滑入，带中等震动。

### 编译报错修复（v2）

- 第一次实现的 `body` 用了 `var result = content; result = result.gesture(...)` 反复赋值——失败，
  因为 `.offset`/`.gesture`/`.onChange` 每次返回不同的 `ModifiedContent<...>` 具体类型，
  不能赋回给 `var result: Content`（泛型 `Content`）。
- 修正方案：**手势永远挂在树上**，把 `enabled` 放进 `onChanged`/`onEnded` 的 guard 里做"惰性"——禁用时
  手势完全 inert，并且把 `dragOffset` 钳到 0。再加一个 `.onChange(of: enabled)` 在 `enabled` 翻成 false
  的瞬间把 `dragOffset` 归零（应对歌词/队列在滑动途中打开的边角情况）。
- 这样 `body` 保持单表达式链式（原来就编译通过的形式），不需要 `@ViewBuilder` 分支，
  也不需要把 `enabled` 透传成"条件挂载/不挂载"的异构 `some View` 返回。
- 为什么不在父视图用 `if enabled { ... }` 条件挂 modifier：父视图（`surfaceStack`）的返回是 `some View`，
  分支会引入 `_ConditionalContent`，改动面更大；现在的"惰性挂载 + onChange 复位"方案改动最小、风险最低。
